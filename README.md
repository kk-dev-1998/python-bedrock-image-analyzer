# python-bedrock-image-analyzer
AWS Bedrockを利用した画像解析API。  
FAST APIを使ったAPIで、アップロードされた画像に写っている物体が何か・どこのメーカの製品かを解析する。  

The API analyzes uploaded images using AWS Bedrock.  
Built with FASTAPI, It analyzes the object in the image and return what is this and which company provide the object.  

---

## Architecture

```
[Client] -> POST /analyze (image) -> [FastAPI] -> [AWS Bedrock] -> JSON Response
```

インフラ（AWS Lambda / API Gateway / S3 / IAM）はTerraformで別リポジトリ管理しています。
→ [python-bedrock-image-analyzer-infra](https://github.com/kk-dev-1998/python-bedrock-image-analyzer-infra)

## Getting Started

### Prerequisites
- AWS Account
- Docker (Optional)

### Setup

1. Clone repository

```bash
git clone https://github.com/kk-dev-1998/python-bedrock-image-analyzer.git
cd python-bedrock-image-analyzer
```

2. Set environment variables

```bash
cp .env.example .env
# Update your AWS credentials
```

3. Create and enable virtual environment

```bash
python -m venv .venv

# Mac/Linux
source .venv/bin/activate

# Windows
.venv\Scripts\activate
```

4. Install dependencies

```bash
pip install -r requirements.txt
```

5. Launch

```
uvicorn app.main:app --reload
```

5. Open API docs in browser

```
https://localhost:8000/docs
```

### Docker

```bash
# Build
docker build -t bedrock-image-analyzer
# Run
docker run --env-file .env -p 8000:8000 bedrock-image-analyzer
```

## Evaluation

画像解析の出力品質を、固定のテストケースで定量評価するスクリプトです(Bedrockを実際に呼ぶため、費用がかかります)。
A script that scores the model output against fixed test cases. It calls Bedrock for real, so it costs money.

```bash
python -m evaluation.run_eval --repeat 3 --sleep 10
```

### How it works
- 10 cases, each run 3 times (30 calls). Output is scored per field (`name_of_item`, `brand`, `color`, `serial_number`) against accepted values. `NA` must match exactly, so a hallucinated brand fails a no-logo case.
- 5 cases use synthetic images generated by `evaluation/make_synthetic_images.py` (serial number visible, PNG, WebP, prompt injection, not-an-object).
- 5 cases use real photos (clear logo, no logo, multiple objects, small object, low quality). The photos are not published; they are git-ignored and listed in `evaluation/cases.private.json`.
- Results are written to `evaluation/results/` (git-ignored).

### Results (Claude Haiku 4.5, 10 cases x 3 runs, 2026-11-03)

| Run | Change | Case pass rate | Errors |
|---|---|---|---|
| 1 | baseline | 24/30 (80%) | 5 (4x `detail` over 50 chars, 1x throttling) |
| 2 | retry once on invalid output | 25/30 (83%) | 2 (throttling) |
| 3 | 10 s interval between calls | 28/30 (93%) | 1 (`detail` over 50 chars) |

Run 3 by field: name_of_item 93%, brand 100%, color 97%, serial_number 100%.
Every category passed 3/3 except small_in_background (2/3) and low_quality (2/3).

### Findings
- モデルは、プロンプトで2回指示しているにもかかわらず、「`detail` は50文字以内」というルールを守らないことがあります。対策なしではAPIエラーとして現れました(4/30)。1回リトライすることで全体実行では解消しましたが、ぼやけた画像では今も発生します(case-06のみの実行で1/5)。
- The model sometimes breaks the "`detail` is 50 characters or fewer" rule, even though the prompt says so twice. Without handling, this surfaced as an API error (4/30). Retrying once removed it from the full runs, but it still occurs on blurry images (1/5 in a case-06-only run).
- イヤホン本体が写っていない小さな黒いイヤホン充電ケースを、9回中5回「電源アダプタ」と答えました。誤答を正解として許容せず、期待値は変更していません。
- A small black earbud charging case without earbuds visible was answered as "power adapter" in 5 of 9 runs. I kept the expectation as is instead of accepting the wrong answer.
- スロットリング(`ThrottlingException`)の原因はモデルではなく、連続してAPIを呼んだことでした。スクリプトに `--sleep` を追加しました。
- Throttling (`ThrottlingException`) came from firing calls back to back, not from the model. The script now has `--sleep`.

### Limitations
- サンプリングは `topP: 0.8` のみで制御しています(Claude Haiku 4.5 は `topP` と `temperature` の両方を同時には指定できず、どちらか一方のみ受け付けるため、`temperature` は未指定です)。実行ごとに結果がばらつきます。1回の実行は30呼び出しと少数なので、1〜2ケースの差はノイズとして扱ってください。
-Sampling is controlled by `topP: 0.8` only (Claude Haiku 4.5 accepts either `topP` or `temperature`, not both; `temperature` is left unspecified). Results vary run to run. 30 calls per run is small; treat differences of one or two cases as noise.
- ケースの半分は非公開の写真を使っているため、他の人が完全に再現することはできません。
- Half of the cases use private photos, so they cannot be reproduced exactly by others.

### Next
- リトライ時にモデルへ `detail` の長さを伝える。サンプリングパラメータを調整する。
- Tell the model its `detail` length on retry; tune sampling parameters.
- Claude Haiku 5.5 と比較する。
- Compare with Claude Haiku 5.5.

## AWS Lambda Deployment
AWS Lambdaを利用する場合は、以下の手順を行う。
If you want to use AWS Lambda, execute the below steps.

### Overview

1. Build the container image for Lambda
```bash
   docker build -t python-bedrock-image-analyzer .
```
2. Push the image to ECR
3. Run `terraform apply` in the infra repository (provisions Lambda / API Gateway / S3 / IAM)

Environment variables (region, Bedrock inference profile ID, etc.) are configured automatically
by Terraform, so no manual setup in the Lambda console is required.

> Note: Since a container started with Docker uses the Lambda runtime format,
> it cannot be accessed directly as an HTTP server via `docker run`.
> For local testing, use the uvicorn startup described in "Getting Started" above.
